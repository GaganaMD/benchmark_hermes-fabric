## PURPOSE

`auth/jwt.py` issues JWT access/refresh token pairs, validates access tokens, and exchanges valid refresh tokens for new token pairs. It uses a shared HS256 secret and fixed TTLs: 15 minutes for access tokens and 7 days for refresh tokens.

## FLOW

   2. Creates an access token with `sub`, `iat`, and `exp = now + ACCESS_TTL`. `auth/jwt.py:14` `auth/jwt.py:15`
   3. Signs the access token using `SECRET` and `ALGO`. `auth/jwt.py:16`

   6. Returns both tokens as `{"access": access, "refresh": refresh}`. `auth/jwt.py:22`

   4. If it is a valid refresh token, calls `issue(claims["sub"])` to return a new access/refresh pair. `auth/jwt.py:46`

## EDGE CASES

- Expired access token passed to `validate` — catches `pyjwt.ExpiredSignatureError`, returns `None`.
- Malformed, incorrectly signed, or otherwise invalid access token passed to `validate` — catches `pyjwt.InvalidTokenError`, returns `None`.
- Refresh token passed to `validate` — detected by `claims.get("typ") == "refresh"`, returns `None`.
- Expired refresh token passed to `refresh` — caught as `pyjwt.InvalidTokenError`, returns `None`.
- Malformed, incorrectly signed, or otherwise invalid refresh token passed to `refresh` — catches `pyjwt.InvalidTokenError`, returns `None`.
- Access token or token without `typ == "refresh"` passed to `refresh` — returns `None`.
- Valid refresh token missing `sub` passed to `refresh` — raises `KeyError` from `claims["sub"]`.

## GOTCHAS

- Refresh tokens cannot be used as access tokens: `validate` rejects any token with `typ == "refresh"`.
- Access tokens issued by this module do not include a `typ` claim; `validate` accepts tokens as long as `typ` is not `"refresh"`.
- `refresh` requires `typ == "refresh"`; a token missing `typ` is rejected there.
- Expired access tokens and invalid access tokens both produce the same sentinel result: `None`.
- Expired refresh tokens and invalid refresh tokens also produce `None`.
- Changing `SECRET` will invalidate previously issued tokens because both `validate` and `refresh` decode using the current `SECRET`.
- No custom clock skew or leeway is configured in this module; decoding uses PyJWT’s default expiration handling.
- `refresh` assumes a valid refresh token contains `sub`; if that claim is absent, it does not return `None` and instead raises `KeyError`.

## Role
You are a senior distributed-systems reliability engineer and incident responder.

## Task
Improve the reliability of flaky background workers in a production system.

## Context
Treat the request as real-world and actionable. If details are missing, make reasonable assumptions and explicitly label them.

## Instructions
Provide a practical reliability improvement plan with the following sections:

1. **Likely Failure Modes (Ranked)**
   - List the top failure modes causing worker flakiness.
   - For each: symptom, probable root cause, and business impact.

2. **Immediate Stabilization (Next 24–72 Hours)**
   - Concrete, low-risk actions to reduce incidents quickly.
   - Include retries (with backoff + jitter), idempotency protections, timeout strategy, circuit breakers, dead-letter queue handling, and safe deploy/rollback steps.

3. **Observability and Alerting**
   - Define logs, metrics, traces, and dashboards needed to detect and diagnose issues.
   - Include specific SLO/SLI suggestions (e.g., success rate, queue latency, time-to-drain, retry rate, DLQ depth) and alert thresholds.

4. **Durable Architecture Improvements (Next 2–6 Weeks)**
   - Propose medium-term design changes for reliability and scalability.
   - Cover queue semantics (at-least-once/exactly-once tradeoffs), deduplication, poison message strategy, worker autoscaling, graceful shutdown, and backpressure.

5. **Implementation Roadmap**
   - Prioritized plan with phases, owners/roles, dependencies, and estimated effort.
   - Include risk level and expected reliability impact per item.

6. **Validation and Testing**
   - Explain how to verify each change works.
   - Include load tests, fault injection/chaos tests, replay testing, canary strategy, and rollback criteria.
   - Define success metrics and acceptance gates.

7. **Runbook**
   - Provide an on-call runbook for common incidents (worker crash loops, queue backlog spikes, DLQ growth, dependency outage).
   - Include triage steps, mitigation actions, escalation rules, and postmortem checklist.

## Output format
- Use clear Markdown headings for each section.
- Use concise bullets and short tables where useful.
- Include a final **“Top 5 Actions to Do First”** checklist.
- If critical context is missing, start with up to **7 clarifying questions**, then proceed with assumptions and the full plan anyway.
